Parent: `6409ff3fb1d093acac0f97a5cb22e1a8c2acabfc`, feature/cross-platform-lan-hosting. Owner rejected physical v17 IP join with “Web page unavailable”. No phone/device access was used during this correction.

## Confirmed defects and corrections

- Native IP join destroyed the local game and navigated to a remote HTML download without checking readiness. Unreachable HTTP therefore replaced the game with a browser failure screen. Join now performs a bounded, no-redirect `/status` check (identity, protocol, transport, pinned bundle and capacity); failure leaves the current game intact with Find/Retry/Back. Stale callbacks cannot replace a newer screen.
- The selected-host WebView origin is now virtual: `shouldInterceptRequest` serves the exact APK's `phone-host` UI/scripts/textures/audio using `LanPagePolicy`, including the main document. It never falls through to remote HTTP for UI. Only the real WS/WSS connection uses the chosen host. This preserves existing same-origin WebSocket validation without a JavaScript bridge or mixed-content exemption. Native readiness remains actual network HTTP/HTTPS. Main release cleartext denial, fixed approved TLS host, certificate validation and secure transport policy are unchanged.
- Android discovery incorrectly validated interface-derived broadcast targets with a host-only check that rejected last octet 255. Thus normal `/24` broadcasts were discarded before sending. The new executed Java policy accepts RFC1918 broadcast destinations while manual host input still rejects broadcast/public/invalid addresses.
- The bundled HTTPS offline page's advanced Connect action previously entered generic secure-page logic, selecting appassets WSS instead of the supplied LAN IP. It now routes a user gesture through the existing native URI dispatcher, normalizes the private host and runs the same readiness/join path. Non-Android behavior is unchanged. V17's exact host bundle remains an explicit compatible pin.
- Create/Find remain the ordinary entry points; manual IP is fallback. No gameplay/server authority, HUD51 layout, camera/ADS, hit detection, simulation, listener binding or LAN protocol changes. Both Android and Windows servers still bind their selected Wi-Fi address, not localhost (tests deliberately bind only loopback).
